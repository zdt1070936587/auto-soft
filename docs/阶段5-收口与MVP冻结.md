# 阶段 5：收口与 MVP 冻结（完整开发计划）

> 文档日期：2026-08-20  
> 对应总计划：[分阶段开发计划.md](./分阶段开发计划.md)  
> 前置：阶段 1～4 功能已可演示（登录、动态 CRUD、工作室、单线审批）  
> 工期：3～4 人天  
> 目标：安全与体验收口、文档齐备、端到端走查通过后冻结 MVP。不新开大功能。

---

## 1. 阶段目标

1. 动态接口与 Agent 工具的鉴权、标识符白名单、参数校验做一次专项复查并补测。
2. 发布/回滚（或取消发布）行为明确；会话列表与用量可见；Go 429 友好提示稳定。
3. 操作日志覆盖：用户维护、角色授权、发布、流程提交/通过/驳回。
4. 写出 `docs/api.md`、`docs/user-guide.md`，更新 `dev-setup` / `database`。
5. 端到端：登录 → 对话生成带审批的功能 → 发布 → USER 使用 → ADMIN 审批。
6. 明确「首期不做」清单，避免范围回潮。

## 2. 本阶段明确不做（冻结）

写 Java/Vue 热加载；复杂报表/图表；多租户；自定义脚本；会签/条件分支；移动端；Refresh Token（若阶段 1 未做则本阶段**仍可不做**，除非走查认为 8 小时 token 不可接受，仅允许加「续期接口」不改成复杂轮换）。

简易 schema 手工编辑：若阶段 3 模型不稳定，本阶段**允许**在建模页补字段表格（阶段 2 已有则打磨），作为 Agent 失败兜底，不算新大功能。

## 3. 安全收口（优先当天完成）

复查清单（每条要有结论：已有 / 已补 / 风险接受）：

| 项 | 要求 |
| --- | --- |
| 运行时 SQL | 列名/表名/排序字段仅元数据白名单；值全部 bind |
| DDL | 仅 `dyn_` + code 正则；无 DROP |
| 工具参数 | 与 MetaService 同一套校验，不信任模型 |
| 越权 | USER 不能 preview 他人草稿；不能猜 taskId 审批；不能调 `/api/meta/**` |
| 密钥 | LLM Key、JWT secret、AES key 不进日志、不进操作日志详情 |
| 文件 | 本阶段若仍无上传则跳过；有上传必须类型与大小限制 |
| CORS | 生产不得用 `*`；dev 仅 localhost:5173 |
| 健康检查 | actuator 细节仅授权或本机 |

补：全局 `traceId`（MDC + `R.traceId`），方便对照操作日志。阶段 0 已预留字段则接上。

可选：登录失败次数告警只打日志，不做验证码（防范围膨胀）。

## 4. 发布与回滚

产品规则写进 user-guide：

- **发布**：DDL ensure + 菜单可见 + version+1
- **取消发布**：菜单隐藏，数据与表保留
- **回滚草稿**：不支持 DDL 回滚；只支持元数据草稿覆盖未发布改动  
  若已发布要「回到上一版 schema」：**MVP 不做自动回滚**，文档写明「新增字段可再发，已加列不删除」

会话列表：工作室首页列出历史 session、token 累计、关联 app。用量：设置页或工作室顶栏展示本会话 input/output tokens；429 文案统一。

### docs/user-guide.md

## 8. 端到端走查脚本（必须当场执行）

准备账号：`admin`（超管）、`dev1`（DEVELOPER）、`user1`（USER）、`admin2`（ADMIN 审批人）。

1. `dev1` 登录工作室，配置已由超管写好 Key。  
2. 输入：「做请假单，字段请假天数（数字）、原因（多行文本），提交后要 ADMIN 角色审批」。  
3. 确认字段后发布，授权 USER。  
4. `user1` 看到菜单，填写提交。  
5. `admin2` 待办通过；`user1` 看到已通过、表单只读。  
6. 再测驳回分支。  
7. `user1` 不能打开建模页、不能改 LLM Key。  
8. 超管打开操作日志能看到发布与审批记录。  
9. 停库再启，Flyway 不报校验失败。

将结果记入本文或 `docs/e2e-mvp.md` 短记录（日期、通过/缺陷）。

## 11. 风险

| 风险 | 处理 |
| --- | --- |
| 走查当天模型不稳定 | 用阶段 2 手工建模 + 阶段 4 手工绑流作为备份路径，工作室作为加分项但仍应力争主路径通过 |

## 12. MVP 冻结后

二期候选（不在本阶段做）：Refresh Token、会签、schema 版本回滚、物理删列、多租户、移动端、Responses 协议补全、导入导出。

新需求进独立文档或 issue，不直接改冻结接口的语义。
