# 阶段 0：脚手架与规范（完整开发计划）

> 文档日期：2026-08-20  
> 对应总计划：[分阶段开发计划.md](./分阶段开发计划.md)  
> 工期：1～2 人天  
> 目标：仓库可克隆、可启动、可连库、可健康检查；规范文档齐备。本阶段**不实现登录、用户、CRUD、Agent、工作流**。

---

## 1. 阶段目标

阶段 0 只做「能跑起来的空工程 + 全员遵守的规范」，为阶段 1 起的业务开发铺路。

必须同时满足：

1. `dev` 用 JDK 25 编译通过，Spring Boot 进程可启动。
2. PostgreSQL 可连接，Flyway 至少成功执行 1 条基线脚本。
3. 浏览器打开前端骨架页，并能调用后端健康接口拿到统一 JSON。
4. `docs/` 写清如何启动、如何分层、库表约定。
5. 代码从第一行就符合阿里分层：Controller 零业务。

## 2. 本阶段明确不做

以下内容一律放到后续阶段，阶段 0 出现即视为范围失控：

| 内容 | 放到 |
| --- | --- |
| 登录页太阳系动效、JWT、Spring Security | 阶段 1 |
| 用户 / 角色 / 菜单表与页面 | 阶段 1 |
| 元数据引擎、动态表、SchemaRenderer | 阶段 2 |
| OpenCode Go、对话工作室 | 阶段 3 |
| warm-flow 依赖与流程表 | 阶段 4 |
| Redis、消息队列、Docker 镜像发布 | 非 MVP 或更后 |
| 业务 Controller / 真实 CRUD | 阶段 1 起 |

阶段 0 可以引入 MyBatis-Plus **依赖与空配置**，但不要写业务 Mapper。

## 6. 后端详细设计

### 6.1 Maven 模块职责

| 模块 | packing | 依赖谁 | 阶段 0 要做什么 |
| --- | --- | --- | --- |
| `auto-soft`（父） | pom | Boot BOM | 统一版本、插件、模块列表 |
| `auto-soft-common` | jar | 无业务依赖 | `R`、错误码、异常、分页对象、工具类 |
| `auto-soft-framework` | jar | common | CORS、Jackson、校验失败处理、WebMvc 配置 |
| `auto-soft-system` | jar | framework | 仅 `package-info.java` |
| `auto-soft-meta` | jar | framework | 仅 `package-info.java` |
| `auto-soft-agent` | jar | framework | 仅 `package-info.java` |
| `auto-soft-flow` | jar | framework | 仅 `package-info.java` |
| `auto-soft-boot` | jar | 上述全部 | 启动类、配置、Flyway、健康接口 |

依赖方向只能向下，禁止 `common` 依赖 `system`。`boot` 是唯一可依赖所有业务模块的聚合点。

### 6.2 父 POM 关键版本（锁定）

在 `dev/pom.xml` 的 `<properties>` 锁定，后续阶段改版本只改这一处：

| 属性 | 建议值 | 备注 |
| --- | --- | --- |
| `java.version` | `25` | 必须 |
| `spring-boot.version` | `4.1.0` | 当前 4.1 线稳定版；若 Central 已有 patch 用最新 4.1.x |
| `mybatis-plus.version` | `3.5.15+` | 需带 `mybatis-plus-spring-boot4-starter` |
| `postgresql.version` | 跟 Boot BOM | 不要手写过旧驱动 |
| `flyway.version` | 跟 Boot BOM | PostgreSQL 需要 `flyway-database-postgresql` |
| `lombok.version` | 跟 Boot BOM | 允许使用，禁止在 Controller 里写业务后用 Lombok 掩盖复杂度 |

Spring Boot 4 注意点：

- Web 起步依赖使用 **`spring-boot-starter-webmvc`**，不要再用 Boot 2/3 的 `spring-boot-starter-web`（4.x 已拆分）。
- Actuator 使用 `spring-boot-starter-actuator`。
- 校验使用 `spring-boot-starter-validation`。
- JDBC 使用 `spring-boot-starter-jdbc`（阶段 0 健康检查与 Flyway 足够；MyBatis-Plus 可在 boot 中引入但暂不写 XML Mapper）。

父 POM 插件：

- `spring-boot-maven-plugin` 只挂在 `auto-soft-boot`
- `maven-compiler-plugin`：`release=21`，开启 `-parameters`
- `maven-enforcer-plugin`：要求 JDK 25
- 推荐：`p3c-pmd` 或 IDEA 阿里规范插件；阶段 0 至少在 `docs/coding-standards.md` 写明检查方式，插件可在阶段 0 下午加上

### 6.5 统一返回与异常（必须在阶段 0 落地）

这是后续所有接口的底座，阶段 0 就要用健康检查跑通。

包结构：

```
com.autosoft.common
  core
    R.java                 # 统一包装
    ResultCode.java        # 枚举：SUCCESS/FAIL/BAD_REQUEST/NOT_FOUND/SERVER_ERROR
    PageQuery.java         # current、size，默认 1 / 10，size 上限 200
    PageResult.java        # total、records
  exception
    BizException.java      # 业务异常，带 ResultCode
    GlobalExceptionHandler.java  # 可放 common 或 framework；推荐 framework
  utils
    AssertUtils.java       # 空值断言，抛 BizException
```

`R<T>` 字段（JSON）：

- `code`：`Integer`，成功 `0`（与阿里手册「错误码」习惯对齐，前端只判断 `code === 0`）
- `msg`：`String`
- `data`：`T`
- `traceId`：可选，阶段 0 可先空，阶段 5 再接 MDC

`GlobalExceptionHandler` 必须处理：

1. `BizException` → 对应业务码
2. `MethodArgumentNotValidException` / `BindException` → 400，拼接字段错误
3. `ConstraintViolationException`
4. `Exception` → 500，日志打完整栈，**响应不返回堆栈**

Handler 放在 `framework`，用 `@RestControllerAdvice(basePackages = "com.autosoft")`。

### 6.6 健康检查接口（示范分层，禁止把 SQL 写进 Controller）

| 层 | 类 | 职责 |
| --- | --- | --- |
| Controller | `com.autosoft.boot.web.HealthController` | `@GetMapping("/api/health")`，只调 Service，返回 `R<HealthVO>` |
| Service | `com.autosoft.boot.health.HealthService` | 编排：读应用名 → 探活数据库 → 组装 VO |
| Manager | `com.autosoft.boot.health.DbHealthManager` | 执行 `SELECT 1`，捕获异常转成「库是否可达」 |
| VO | `com.autosoft.boot.health.HealthVO` | `appName`、`profile`、`db`（UP/DOWN）、`now` |

`HealthService.check()` 主方法只写步骤，例如：

1. `fillAppInfo(vo)`
2. `fillDbStatus(vo)`
3. `fillServerTime(vo)`

Controller 示例伪代码（实现时按此结构，不要加分支业务）：

```java
@GetMapping("/api/health")
public R<HealthVO> health() {
    return R.ok(healthService.check());
}
```

同时保留 Actuator：`GET /actuator/health`。前端骨架调用 `/api/health`，运维/探活可用 actuator。

### 6.7 CORS 与 Jackson（framework）

`WebMvcConfig`：

- 开发环境允许 `http://localhost:5173`
- 允许 `GET,POST,PUT,DELETE,PATCH,OPTIONS`
- 允许常见 Header（`Authorization`、`Content-Type`）

Jackson：

- Java 8 时间模块（Boot 4 默认一般已带）
- 日期序列化为 ISO-8601
- 未知属性不失败（`fail-on-unknown-properties: false`），避免前后端字段演进直接 500

阶段 0 **不**加 Spring Security。所有接口暂时可匿名访问。阶段 1 再收口。

### 6.8 日志

`logback-spring.xml`：

- 控制台输出：时间、level、thread、logger、msg
- 文件输出可选：`./logs/auto-soft.log`，按天滚动
- 禁止打印密码、token（阶段 1 登录时再强调；阶段 0 文档写进规范）

### 6.9 Flyway 基线脚本

文件：`dev/auto-soft-boot/src/main/resources/db/migration/V1.0.0__init.sql`

版本号规则（写入 `docs/database.md`）：`V主.次.补丁__英文简述.sql`，只增不改已执行脚本。

阶段 0 脚本内容（证明迁移可用，不为业务表抢跑）：

```sql
-- 阶段 0 基线：仅用于验证 Flyway。业务表从阶段 1 的 V1.1.0 开始。
CREATE TABLE IF NOT EXISTS sys_schema_meta (
    id          BIGSERIAL PRIMARY KEY,
    phase       VARCHAR(32)  NOT NULL,
    remark      VARCHAR(256) NOT NULL,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE sys_schema_meta IS 'schema 迁移备注，非业务表';

INSERT INTO sys_schema_meta (phase, remark)
VALUES ('phase-0', 'flyway baseline');
```

启动后检查：

1. 日志出现 Flyway migrate success
2. 库中有 `flyway_schema_history`
3. `sys_schema_meta` 有 1 行

### 8.4 `docs/coding-standards.md`

必须写清并作为 Code Review 清单：

1. 分层：Controller / Service / Manager / Mapper；Controller 禁止业务、禁止调 Mapper。
2. 复杂方法：主方法只写步骤；单方法超过 80 行建议拆，超过 150 行必须拆。
3. 命名：UpperCamelCase 类名；lowerCamelCase 方法；常量 `UPPER_SNAKE`；包名全小写。
4. 禁止魔法值：状态用枚举。
5. 异常：业务走 `BizException`；禁止 `e.printStackTrace()`；禁止吞异常。
6. 日志：禁止输出密码、token、身份证号。
7. API：统一 `R<T>`；URL 名词复数或资源风格，阶段 1 起 `/api/users`。
8. 注释：类与 public 方法中文说明「做什么」；不写无意义的 getter 注释。
9. 前端：组件文件 PascalCase；API 模块按领域拆分。
10. Git：commit 信息中文或英文祈使句，禁止 `update` 这种空信息（阶段 0 在文档中约定即可）。

## 11. 风险与处理

| 风险 | 处理 |
| --- | --- |
| Spring Boot 4 起步依赖名称变化导致无法解析 | 以 Maven Central 上 `4.1.x` 的 `spring-boot-starter-webmvc` 为准；编译失败时查 Boot 4.1 发行说明，不降回 Boot 3 |
| MyBatis-Plus 与 Boot 4 坐标不熟 | 阶段 0 可以只用 JDBC 做 `SELECT 1`；MP starter 放进父 POM 但 boot 暂不强制引入，阶段 1 再接 |
| Windows 5432 已被本机 PostgreSQL 占用 | compose 改 `15432:5432`，yml 同步 |
| Flyway 与本地脏库冲突 | 开发库可删卷重建：`docker compose down -v`（仅限本地空库） |
| 前端代理 404 | 确认 Vite proxy 与后端 `context-path` 均为 `/`，接口带 `/api` |
| 编码规范无法自动检查 | 阶段 0 以文档 + Review 为准；有余量再加 p3c-pmd |
