# 使用指南（MVP）

## 1. 登录

浏览器打开 [http://localhost:5173](http://localhost:5173)。开发库默认密码均为 `admin123`（**生产必须改密**）：

| 用户名 | 角色 | 用途 |
| --- | --- | --- |
| `admin` | 超级管理员 | 用户、角色、模型设置、操作日志 |
| `demo_admin` | 管理员 | 用户/角色、审批待办 |
| `demo_dev` | 开发者 | 应用建模、功能开发工作室 |
| `demo_user` | 普通用户 | 已授权的动态功能、提交单据 |

详见 [dev-setup.md](./dev-setup.md)。

## 2. 管理员如何建用户、分角色

1. 用 `admin` 或 `demo_admin` 登录。
2. 「用户管理」新建账号并勾选角色：`ADMIN` / `DEVELOPER` / `USER`。
3. 「角色管理」可改菜单授权。内置角色不要删。
4. 公开注册默认关闭。

## 3. 配置模型（仅超管）

1. 打开「模型设置」。
2. 粘贴 OpenCode Go API Key（只写不回显，库中 AES-GCM 密文）。
3. 默认模型建议 `kimi-k2.7-code`（Chat Completions）。不要默认选高单价模型。
4. 额度约 $12/5 小时、$30/周、$60/月。429 时换模型或稍后。

## 4. 开发者如何提需求

路径 A（推荐）：「功能开发」新开会话，例如：

> 做请假单，字段请假天数（数字）、原因（多行文本），提交后要 ADMIN 角色审批。

确认字段中文名后再让助手建结构。右侧是草稿预览。点 **发布** 并二次确认。

路径 B（兜底）：「应用建模」手工建 app / 实体 / 字段后发布。

一次会话只改一个应用。不要让模型写 Java/Vue 文件——系统也不会写。

路径 C（工作流）：在工作室描述步骤，例如「根据合同 ID 查已发布合同，金额大于 1000 走提醒，否则结束」。助手生成图后，右侧可改节点与 **true/false** 连线，**试跑**后再发布。人审节点走现有「待办中心」；通过后工作流继续，驳回则运行失败。可用「分享」生成只读链接，复制草稿不含密钥。表单提交（`trigger=form`）会触发已发布工作流。定时与 HTTP 仅开发配置：HTTP host 必须在白名单，超管可关停定时。

## 5. 发布、填单、审批

- **发布**：建 `dyn_{app}_{entity}` 表（只加列不删列）、生成菜单、version+1。授权角色（默认 USER）刷新菜单后可见。
- **取消发布**：菜单隐藏，表和数据保留。
- **不支持** DDL 回滚或回到上一版 schema。
- USER 在动态页填写，绑定流程后先保存再 **提交**。审批中/已通过只读。
- ADMIN 在「待办中心」通过或驳回（驳回必填意见）。驳回后提交人可改再提交（新实例）。

## 6. 额度与 429

设置页或工作室顶栏可看本会话 token。若提示「额度或限流，请更换模型或稍后」，换 Chat 模型或等待配额窗口。无 Key 时提示去模型设置。

## 7. 首期做不到什么

写 Java/Vue 并热加载；复杂报表；多租户；自定义脚本节点；会签/或签；Refresh Token；自动回滚已加列。

工作流 HTTP 必须配置 `autosoft.workflow.http.allowed-hosts`，未进白名单不能发布。定时最小间隔 5 分钟，同一工作流同时只跑一个实例。

## 8. 全局 AI 助手（阶段 7）

登录后任意后台页面右下角有 **AI 机器人** 浮动按钮，点击展开侧滑对话窗。

**能做什么：**

- **找菜单**：例如「用户管理在哪里」→ 返回可点击链接，跳转前校验你的菜单权限。
- **查操作**：例如「我昨天有没有新增过用户」→ 基于系统操作日志如实回答；可展示前后操作时间线。
- **查浏览（P4）**：例如「我昨天有没有打开用户管理页」→ 基于页面访问埋点如实回答（仅记录启用 P4 之后的浏览）。
- **跨会话记忆（P2）**：例如告知「我叫张三，负责财务」，新会话问「我叫什么」仍可回答；助手会在对话中调用 `remember_fact` / `recall_user_memory`。
- **记忆管理（P3）**：对话窗顶栏 **记忆** 按钮，可查看、确认或删除助手记住的画像/偏好。
- **闲聊**：非系统问题也可正常对话。
- **代操作（阶段 8）**：例如「帮我在用户管理新建用户张三，角色管理员」→ 助手搜索能力、校验字段，展示 **操作计划** 卡片；点 **确认并前往** 跳转到用户管理（或动态 CRUD 页）并预填表单，你在目标页核对后点 **保存** 才写入数据库。缺字段时会提示还需填写的内容；助手不会在对话里直接代你提交。

**做不到什么：**

- 不能代替「功能开发」改应用/实体/工作流。
- 不能查看他人的操作记录或浏览记录。
- 浏览记录不含 URL 查询参数，且仅覆盖后台 AdminLayout 内页面（不含 H5）。
- 不能跳过目标页确认直接写库（无「一键代提交」）。

与「功能开发」会话完全分离；刷新页面后会会话 ID 保存在当前浏览器标签页。未确认的画像在注入 Prompt 时会标注「待确认」。

更多设计见 [阶段7-全局AI助手与记忆系统.md](./阶段7-全局AI助手与记忆系统.md)、[阶段8-助手操作Copilot.md](./阶段8-助手操作Copilot.md)。
